## 阶段 1：知识库 ⬜ 下一步

**交付成果**：可用的个人知识库。
**完成标准**：数据持久化、版本可追溯。

计划实施顺序（9 步）：

| # | 任务 | 关键点 |
|---|---|---|
| 1 | `backend/domain/versioning.py` | 追加式版本的核心规则：新版本永不覆盖旧版本 |
| 2 | `backend/schemas/knowledge.py` | Pydantic 校验；状态与来源类型的取值约束放在这一层 |
| 3 | `backend/services/knowledge_service.py` | 创建/读取/更新/归档；每次重要修改生成新版本 |
| 4 | `backend/services/search_service.py` | FTS5 trigram + LIKE 兜底的混合检索（见 DECISIONS） |
| 5 | `backend/api/knowledge.py` | REST 接口 |
| 6 | 后端测试 | 覆盖 CRUD、版本追溯、归档、搜索、原文不被覆盖 |
| 7 | 前端 `lib/api.ts` + 知识库列表页 / 详情页 / 新建编辑表单 | 字段尽量少，避免记录本身成为负担 |
| 8 | 前端类型检查与构建 | `tsc -b` 零错误 |
| 9 | 更新文档 | DATA_MODEL、ARCHITECTURE、本文件 |

**阶段 1 验收标准**：

- [ ] 可以创建、查看、编辑和归档知识单元
- [ ] 知识字段：名称（必填）、所属领域、自己的理解（必填）、理解依据、尚存疑问、学习来源
- [ ] 用户原始理解不会被覆盖，历史版本可查看
- [ ] 每次重要修改创建新版本，可查看版本列表
- [ ] 中文搜索可用（「梯度」这类 2 字词也能搜到）
- [ ] 归档而非物理删除，归档项默认不显示
- [ ] 应用重启后数据仍然存在
- [ ] 手机端窄屏下主要流程可完整操作

## 阶段 2：AI 教练 ⬜

**交付成果**：AI 辅助记录与纠错。
**完成标准**：结构化输出可校验，原文不被覆盖。

- 模型 Provider 抽象层（支持 OpenAI API 及兼容接口，不锁定单一供应商）
- 设置页：API 地址、密钥、模型名、超时
- AI 学习室：自由对话
- 知识提取工作流：对话 → 结构化草稿 → 用户确认 → 正式知识
- 知识审查工作流：正确点 / 错误 / 遗漏 / 追问 / 待核实，后端做 Schema 校验
- AI 反馈独立存储，用户决定是否采纳

**验收标准**：

- [ ] AI 能从对话中生成结构化草稿，用户确认后才保存
- [ ] AI 能对知识理解生成结构化审查结果，且通过后端 Schema 校验
- [ ] 用户原始理解不会被 AI 修改覆盖
- [ ] 草稿明确区分「来自用户」与「AI 补充」
- [ ] AI 服务不可用时，手动知识记录和浏览历史知识仍可使用
- [ ] 模型 API Key 不出现在前端代码、日志或版本库中
- [ ] 长时间 AI 任务显示加载状态，不会重复提交造成重复记录

## 阶段 3：复习系统 ⬜

**交付成果**：学习—复习闭环。
**完成标准**：复习评级正确更新计划。

- 集成 FSRS（使用成熟实现，不自制间隔算法）
- `review_schedules` / `review_sessions` 表迁移
- 复习中心：到期任务列表
- 对话式复习：AI 提问 → 用户回答 → AI 追问 → AI 评价 → 用户确认评级
- 复习历史记录

**已知技术风险（提前记录）**：

`fsrs` 6.3.2 的 `Card` 字段是 `card_id, state, step, stability, difficulty, due, last_review`，
而 Blueprint 的 `review_schedules` 还列了 `reps, lapses, elapsed_days, scheduled_days`。
这四个字段需要由 `review_sessions` 的历史记录推算，不能指望 FSRS 库直接给。
另外测试必须用 `Scheduler(enable_fuzzing=False)`，否则结果不确定、测试无法断言。

**验收标准**：

- [ ] 复习中心能按到期时间列出知识
- [ ] 复习流程包含 AI 提问、用户回答、AI 反馈和用户最终评级
- [ ] AI 只给评级建议，最终评级由用户确认或修改
- [ ] AI 不提前泄露答案，回答不完整时继续追问
- [ ] FSRS 状态能在复习后正确更新，且可查看下次复习时间
- [ ] 保存问题、回答、评价、评级、耗时和下次复习时间
- [ ] 系统时间变化、跨日和时区转换不会导致复习日期错乱

## 阶段 4：知识网络 ⬜

**交付成果**：可审核的个人知识图谱。
**完成标准**：未审核关系不进入正式图谱。

- 候选召回（关键词 / 全文 / 向量，只召回少量相关知识，不做全库无差别扫描）
- 关联判断工作流：关系类型 + 解释 + 依据 + 置信度
- `knowledge_relations` 表迁移，状态 pending / accepted / rejected
- 待审核列表：确认、拒绝、修改类型、暂时忽略
- 图谱可视化（React Flow 或 Cytoscape.js）
- 成长统计

**验收标准**：

- [ ] 新增知识后能生成有解释和依据的候选关联
- [ ] 用户可以确认、拒绝或修改候选关系
- [ ] 正式知识图谱只显示已确认（accepted）的关系
- [ ] 被拒绝的候选保留审核记录，不会重复骚扰
- [ ] 可以按领域查看知识，并浏览相关知识
- [ ] 成长统计基于真实记录，不使用虚构或推测数据

**交付成果**：手机可访问的应用。
**完成标准**：窄屏主要流程可完整操作。

## 明确不做的内容

以下功能在第一版**明确不做**，不要擅自添加：

- 完整 PDF 阅读器、网页剪藏、视频字幕自动采集、浏览器自动抓取
- 多人协作、公开社区、排行榜、社交功能
- 复杂 3D 知识图谱或大型图数据库
- 自动生成完整课程、自动规划所有学习活动
- 多设备云同步和账号体系
- 原生 Android / iOS 客户端
- 自动覆盖用户笔记，或未经审核自动建立正式知识关系
- 商业化功能、复杂微服务架构
