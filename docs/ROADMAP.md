**窄屏实测（这次是真的量了，不是推断）**：

内嵌浏览器视口是 **524×605**（低于 Tailwind 的 `md` 断点 768px），所以上面全流程都是在窄屏布局下跑完的：

- 所有输入框 / 下拉框 / 文本域计算高度 **44px**，字号 **16px**
  （16px 不是审美：iOS Safari 聚焦小于 16px 的输入框会自动放大整页）
- 所有按钮 **≥44×44**（实测前修掉了 3 个偏小的图标按钮，见下）
- `document.scrollWidth === clientWidth === 524`，**没有任何元素横向溢出**
- 抽屉导航 6 个入口，每项 50px 高；点导航项后抽屉自动收起
- 分页：21 条数据分成 20 + 1，两页**不重不漏**，翻页按钮 44px 高，首末页正确置灰
- 控制台**零消息**（无 error、无 warning）

实测中修掉的 4 个问题：

1. 搜索无结果的文案拼成「在**在**用的知识里没有匹配项」——状态词加了「」书名号
2. 三个图标按钮触摸目标偏小（顶栏汉堡 36px、抽屉关闭 28px、清空搜索词 28px）——统一强制 `size-11`（44px）
3. `input[type=search]` 在 WebKit/Chromium 下会额外渲染一个原生 ✕，和我们自己画的清空按钮叠在一起——CSS 关掉原生的
4. 抽屉打开时有**两个** `aria-label="关闭导航"` 的按钮（全屏遮罩 + 右上角 X），读屏用户分不清——遮罩改成「关闭导航（点击空白处）」，并补了 Esc 关闭

**已知的诚实限制（不藏）**：

- **标题的演变历史留不下来**——`title` 在主表上，版本表没有标题快照列。
  这是用户知情并选择的取舍（D-030），不是 bug。
- **领域自动补全只能减少、不能消除领域名混乱**——用户仍可无视提示硬打。
  彻底解决需要建字典表，已否决（D-031）。
- **搜索只检索「当前版本」的理解正文**——搜旧版本里写过、当前版本已删掉的词句搜不到。
  实测：「跳过最低点」只存在于 v1，搜索返回 0 条。这与 D-006 的索引设计一致
  （`knowledge_fts` 的正文列 == 当前版本），是取舍不是缺陷；
  若将来要「连历史版本一起搜」，需要给索引加版本维度，属于阶段 3 之后的事。
- **宽屏（≥768px）布局没有做过可视化验证**——内嵌浏览器视口固定 524px 且
  `take_screenshot` 返回 `NATIVE_BROWSER_VIEWPORT_UNAVAILABLE`（页面 surface 处于 hidden），
  所有验证都是结构化的：无障碍树快照 + `getComputedStyle` + `getBoundingClientRect`。
  窄屏因此是**实测**的，宽屏仍是**代码推断**的。阶段 5 需要用真机补一遍。
- **前端持有词表的第三份拷贝**（`lib/schemas.ts` 里的 8 种来源类型、2 种知识来源、
  状态、created_by）以及 `UNDERSTANDING_FIELDS` 的一份拷贝。后端才是权威，
  漂移由后端 OpenAPI 测试兜住，前端 zod 校验失败会**大声报错**而不是静默出错数据。
- **JS 单包 523 kB（gzip 167 kB），超过 Vite 的 500 kB 提示线**，主要是 zod。
  本地单用户应用，首屏加载可接受；先记录不做提前拆包，真有体感问题再按路由做 `dynamic import`。
- **没有 Python lint 步骤**——dev 依赖只有 `pytest` + `httpx2`，ruff 未安装。
- **仓库没有远程备份**——本机 Clash Verge 阻断 github.com，doctor 报 WARN，提交只在本机。

## 阶段 3：复习系统 ⬜

- 复习中心：到期任务列表
- 对话式复习：AI 提问 → 用户回答 → AI 追问 → AI 评价 → 用户确认评级
- 复习历史记录

**已知技术风险（提前记录）**：

`fsrs` 6.3.2 的 `Card` 字段是 `card_id, state, step, stability, difficulty, due, last_review`，
而 Blueprint 的 `review_schedules` 还列了 `reps, lapses, elapsed_days, scheduled_days`。
这四个字段需要由 `review_sessions` 的历史记录推算，不能指望 FSRS 库直接给。
另外测试必须用 `Scheduler(enable_fuzzing=False)`，否则结果不确定、测试无法断言。

**验收标准**：

- [ ] 复习中心能按到期时间列出知识
- [ ] 复习流程包含 AI 提问、用户回答、AI 反馈和用户最终评级
- [ ] AI 只给评级建议，最终评级由用户确认或修改
- [ ] AI 不提前泄露答案，回答不完整时继续追问
- [ ] FSRS 状态能在复习后正确更新，且可查看下次复习时间
- [ ] 保存问题、回答、评价、评级、耗时和下次复习时间
- [ ] 系统时间变化、跨日和时区转换不会导致复习日期错乱

**为什么这一阶段必须有真机**：开发用的内嵌浏览器视口固定 524px 且无法截图，
阶段 1 的窄屏验证是靠无障碍树 + `getComputedStyle` + `getBoundingClientRect` 量出来的，
真机上才会暴露的问题（软键盘顶起布局、iOS 聚焦缩放、触摸滚动惯性、
`http://192.168.x.x:8000` 非安全上下文导致的 API 缺失）在这一阶段要逐项过一遍。
另外宽屏（≥768px）布局至今只做过代码推断，同样需要人眼确认。

## 明确不做的内容

以下功能在第一版**明确不做**，不要擅自添加：

- 完整 PDF 阅读器、网页剪藏、视频字幕自动采集、浏览器自动抓取
- 多人协作、公开社区、排行榜、社交功能
- 复杂 3D 知识图谱或大型图数据库
- 自动生成完整课程、自动规划所有学习活动
- 多设备云同步和账号体系
- 原生 Android / iOS 客户端
- 自动覆盖用户笔记，或未经审核自动建立正式知识关系
- 商业化功能、复杂微服务架构
