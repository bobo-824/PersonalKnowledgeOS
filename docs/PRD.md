## 一、这是什么

一个**本地优先**的个人知识管理与长期学习系统，服务于一个人：本机用户。

它不是笔记软件。笔记软件解决"记下来"，本项目解决"**真的学会了、而且一年后还记得**"。

核心闭环：

```
学习 → 记录 → AI 检验 → 修正 → 主动回忆 → 间隔复习 → 建立知识关联 → 持续积累
  ▲                                                                        │
  └────────────────────────────────────────────────────────────────────────┘
```

关键差别在于：记下来的不是"摘抄"，而是**用户自己的理解**；
而这个理解会被 AI 检验、被时间检验、被反复回忆检验，
每一次检验都留下痕迹，形成可追溯的成长轨迹。

## 二、七条不可违背的设计原则

Blueprint 1.5。**这七条优先级高于任何功能需求。**
当某个功能与原则冲突时，砍功能。

| # | 原则 | 含义 | 违反的样子 |
|---|---|---|---|
| 1 | **用户的理解是核心，AI 是辅助** | 系统记录的是"我怎么理解这个知识"，不是"AI 怎么说这个知识" | 界面上 AI 生成的内容比用户写的更显眼、更容易保存 |
| 2 | **原始记录不可被 AI 覆盖** | 用户原文永久保留。AI 建议、用户确认后的版本，三者必须区分保存 | 采纳 AI 建议时直接 UPDATE 了 `user_understanding` |
| 3 | **复习靠主动回忆，不是重读** | 复习时先让用户自己说，再给反馈。不是把笔记再展示一遍 | 复习页面直接显示答案，用户点"我记得" |
| 4 | **AI 发现的知识关联必须经用户审核** | 未确认的关系不进正式图谱 | AI 觉得两条知识相关就直接连上 |
| 5 | **数据归用户所有，默认本地** | 数据在本机文件里。向 AI 发送时遵循最小必要原则 | 为了"更好的建议"把全库发给模型 |
| 6 | **AI 反馈不是绝对权威** | AI 会说错。用户有权不采纳，且系统不因此降级用户体验 | 不采纳 AI 建议就弹警告、就标红 |
| 7 | **可靠的核心闭环 > 功能数量** | 宁可只有记录和复习两件事但都靠得住 | 一次做八个半成品功能 |

### 原则 2 的技术落点（最重要的那条）

`knowledge_versions` 是**追加式**表：修改理解 = 新增一行，不是改旧行。
`(knowledge_id, version_number)` 有唯一约束。
AI 的建议写进 `ai_revision` 列，与 `user_understanding` **物理隔离**。
用户采纳后**新建一个版本**（`created_by = 'ai_confirmed'`），
旧版本的原文一个字都不变。

`created_by` 的取值只有 `user` 和 `ai_confirmed`——
**没有 `ai`**。AI 不能直接创建版本，这是原则在枚举值层面的体现。

测试 `test_original_understanding_survives_new_version` 直接断言这件事。

## 三、五项核心能力

### 3.1 知识收集（阶段 1）

**目标**：把学到的东西以最低摩擦记下来，且记的是理解而不是摘抄。

字段（Blueprint 5.1，刻意保持少）：

| 字段 | 必填 | 说明 |
|---|---|---|
| 名称 | ✅ | 知识单元标题 |
| 所属领域 | | 自由文本，不做字典表 |
| **自己的理解** | ✅ | **核心字段。用自己的话说清楚** |
| 理解依据 | | "我为什么这么认为" |
| 尚存疑问 | | 阶段 2 的 AI 审查会重点看这里 |
| 学习来源 | | 书 / 文章 / 视频 / 对话，可多条 |

**为什么"自己的理解"必填而"摘要"选填**：
如果允许只写标题就保存，用户会退化成收藏癖——存了 500 条，一条都没学会。
强制写理解，记录本身就成了第一次学习。

其他要求：

- 每次重要修改创建新版本，可查看版本列表
- 中文搜索可用，**「梯度」这类 2 字词也要能搜到**
  （FTS5 trigram 做不到，需要 LIKE 兜底，见 `DECISIONS.md` D-007）
- **归档而非物理删除**，归档项默认不显示
- 应用重启后数据仍然存在

### 3.2 AI 知识教练（阶段 2）

**目标**：检验用户是否真的理解，而不是替用户理解。

三个工作流：

1. **自由对话**：AI 学习室里问问题、讨论
2. **知识提取**：对话 → AI 生成结构化草稿 → **用户确认** → 才成为正式知识
3. **知识审查**：对用户一条已有知识，AI 输出结构化的
   `正确点 / 错误 / 遗漏 / 追问 / 待核实`，后端做 Schema 校验

硬要求：

- 草稿必须明确区分「来自用户」与「AI 补充」
- AI 反馈独立存储，**用户决定是否采纳**
- **AI 服务不可用时，手动记录和浏览历史知识必须仍然可用**
  （这条决定了 AI 集成不能侵入核心数据路径）
- API Key 不出现在前端代码、日志或版本库
- 长时间任务显示加载状态，**不会重复提交造成重复记录**

详细设计见 `AI_WORKFLOWS.md`。

### 3.3 智能复习（阶段 3）

**目标**：在快要忘记的时候，用主动回忆的方式复习。

- 集成 **FSRS**（成熟实现，**不自制间隔算法**）
- 复习中心：按到期时间列出待复习知识
- 对话式复习流程：

```
AI 提问 → 用户回答 → AI 追问（回答不完整时）→ AI 评价 → 【用户确认评级】→ 更新计划
```

硬要求：

- **AI 只给评级建议，最终评级由用户确认或修改**（原则 6）
- **AI 不提前泄露答案**，回答不完整时继续追问（原则 3）
- 保存：问题、回答、评价、评级、耗时、下次复习时间
- **系统时间变化、跨日和时区转换不会导致复习日期错乱**
  （已由 `UTCDateTime` 硬拒绝 naive datetime 在数据层保证，见 D-011）

已知技术风险：`fsrs` 6.3.2 的 `Card` 字段与 Blueprint 的
`review_schedules` 不完全对应，`reps` / `lapses` / `elapsed_days` /
`scheduled_days` 四个字段需要从 `review_sessions` 推算。
详见 `ROADMAP.md` 阶段 3 和 `DATA_MODEL.md`。

### 3.4 知识关联（阶段 4）

**目标**：让知识之间连成网，但**每一条连线都是用户认可的**。

- **候选召回**：关键词 / 全文 / 向量，**只召回少量相关知识，不做全库无差别扫描**
  （全库扫描既慢又会产生海量无意义候选，反而淹没真正有价值的关联）
- **关联判断**：AI 输出 `关系类型 + 解释 + 依据 + 置信度`
  ——没有解释和依据的关联，用户无法判断，等于没给
- **审核**：待审核列表，用户可以 确认 / 拒绝 / 修改类型 / 暂时忽略
- **正式图谱只显示 `accepted` 的关系**
- 被拒绝的候选**保留审核记录，不会重复骚扰**

### 3.5 成长追踪（阶段 4）

**目标**：看见自己的积累。

- 按领域查看知识
- 浏览相关知识
- 统计基于**真实记录**，不使用虚构或推测数据

> **不做排行榜、不做打卡连续天数的社交分享**——
> 这些会把学习动机从"我学会了"扭曲成"我不想断签"。

## 四、页面规划

| 页面 | 路由 | 阶段 | 职责 |
|---|---|---|---|
| 首页 | `/` | 3 | 今日待复习、最近记录、系统状态 |
| 知识库 | `/knowledge` | 1 | 列表、搜索、按领域筛选 |
| 知识详情 | `/knowledge/:id` | 1 | 当前理解、版本历史、来源、相关知识 |
| AI 学习室 | `/study` | 2 | 自由对话、知识提取 |
| 复习中心 | `/review` | 3 | 到期任务、对话式复习 |
| 知识图谱 | `/graph` | 4 | 可视化、候选关联审核 |
| 设置 | `/settings` | 2 | AI 配置、数据备份、导出 |

**当前状态**：只有首页有真实数据（调 `/api/health`）。
其余 6 个页面用 `StagePlaceholder` 明确标注"尚未实现"和所属阶段，
**不放演示数据**——把未实现的功能伪装成已完成，比留白更有害。

## 五、非功能需求

### 5.1 本地优先

- 数据存 `data/app.db`（SQLite + WAL），文件在用户硬盘上
- 无云同步、无账号体系、无遥测
- 默认只监听 `127.0.0.1`

### 5.2 移动端友好

- 主要流程在窄屏下可完整操作
- 触控目标 ≥ 44px（导航项 `min-h-11`）
- **零 hover 依赖**——hover 只做视觉增强，不作为唯一触发方式
- 抽屉式导航，滚动锁定，路由变化自动关闭

阶段 5 补 PWA（可安装到手机主屏幕）。

> **手机访问电脑上的服务，需要在可信局域网内开放访问，
> 并配置防火墙与访问控制。不要默认将服务暴露到公网。**（Blueprint 9.3）

### 5.3 隐私与安全

| 要求 | 落点 |
|---|---|
| API Key 保存在后端环境变量或系统凭据中 | `PKOS_AI_API_KEY` 只在 `.env`，`.env` 在 `.gitignore` |
| Key 不写入前端或提交到 Git | 前端代码没有任何密钥；仓库只有 `.env.example` |
| 日志不记录完整 API Key 或不必要的私人知识正文 | Blueprint 9.1，阶段 2 实现时必须复查 |
| 健康检查不泄露配置 | `/api/health` 只返回 `ai_configured: bool`，有哨兵值测试验证 |
| CORS 不开放 | 白名单只有本机 Vite 源，不是 `*` |
| 静态文件防目录穿越 | `candidate.is_relative_to(dist)` |
| 向 AI 发送数据遵循最小必要 | 只发当前知识单元，不发全库 |

### 5.4 可靠性

- 迁移可 upgrade 可 downgrade，有往返测试
- 外键真的被强制（`PRAGMA foreign_keys=ON`，SQLite 默认不开）
- 时间一律 UTC，写库时硬拒绝 naive datetime
- 健康检查在数据库损坏时返回 `degraded` 而不是 500
- 启动前跑环境自检，端口冲突时报出**占用进程的 PID 和进程名**

### 5.5 可维护性

- 依赖版本锁定到实测通过的稳定版（见 D-002）
- 五层架构，依赖只能从上往下
- 配置单一来源，不散落硬编码
- 每阶段完成后跑测试 + 类型检查 + 构建 + 更新文档，再开始下一阶段
- **不并行开发多个尚未稳定的核心模块**

## 六、明确不做的内容

Blueprint 明确排除，**不要擅自添加**：

- 完整 PDF 阅读器、网页剪藏、视频字幕自动采集、浏览器自动抓取
- 多人协作、公开社区、排行榜、社交功能
- 复杂 3D 知识图谱或大型图数据库
- 自动生成完整课程、自动规划所有学习活动
- 多设备云同步和账号体系
- 原生 Android / iOS 客户端
- **自动覆盖用户笔记**，或**未经审核自动建立正式知识关系**
- 商业化功能、复杂微服务架构

### 开发过程中的行为约束（Blueprint 附录 A）

- **不要用假数据伪装已实现功能**；演示数据必须明确标记
- 遇到需求歧义、破坏性操作或需要上传数据时，**先向用户确认**
- 每阶段结束后按固定格式汇报：
  本阶段完成了什么 / 新增或修改了哪些关键文件 / 如何运行和验证 /
  测试结果及未解决问题 / **与 Blueprint 不一致的地方及原因** /
  下一阶段建议和需要用户确认的决策
